# Контур — учебный участок технических масел

Работающий браузерный прототип: программная SVG-карта участка, экскурсия по семи точкам с отдельными статичными видами с уровня глаз, детерминированная симуляция производства и сравнение сценариев. Реализован на TypeScript, React и Next.js с экспортом статического сайта. Данные синтетические, планировка не является инженерным проектом.

## Запуск

Требуются Node.js, совместимый с установленной версией Next.js (рекомендуется Node.js 22+), и npm.

```bash
npm install
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000). Публичное HTML-описание модели и вычисленные демонстрационные результаты доступны на [http://localhost:3000/model/](http://localhost:3000/model/); для их чтения не нужен клиентский JavaScript.

Проверки и production-сборка:

```bash
npm run typecheck
npm test
npm run build
npm start
```

Сборка создаёт каталог `out/`, который можно обслуживать обычным статическим HTTP-сервером. `npm start` запускает небольшой Node.js-сервер для готового каталога `out/`. Команда `next start` не подходит для `output: 'export'`. При публикации полного приложения следует использовать HTTPS. 

## Сценарий демонстрации

1. На карте пост приёма расположен слева у северного края. Выберите оборудование — панель покажет процесс и текущие показатели.
2. Нажмите маркер камеры P01 или явную кнопку просмотра. Откроется вид участка с уровня глаз и показатели того же текущего прогона.
3. Пройдите кнопками «Предыдущая»/«Следующая» через P01–P07. Вернитесь на карту; Escape закрывает панель, фокус возвращается к точке.
4. Запустите симуляцию, измените скорость воспроизведения, поставьте на паузу или передвиньте модельное время. Кнопка «Рассчитать смену» вычисляет конечный результат сразу.
5. Откройте параметры. Изменения являются черновиком следующего запуска; «Применить и сбросить» явно применяет их к новому прогону.
6. Сохраните сценарий и создайте его копию. В разделе «Сравнение» результаты вычисляются за полную смену; сохранённые результаты текущих прогонов показаны отдельно. При разных поставках/периодах появляется пояснение.

Сценарии и сохранённые результаты хранятся в localStorage текущего браузера, ключ `kontur.scenarios.v1`. При недоступном хранилище приложение продолжает работать без постоянного сохранения.

## Исходные параметры

Начальный набор из задания сохранён без изменений: смена 480 мин, первый автомобиль в 0 мин, далее каждые 45 мин, поставки A/B чередуются, каждая 12 000 л. Вместимость каждого резервуара 80 000 л, начальные остатки каждого 30 000 л. Подготовка машины 5 мин, завершение 3 мин, номинальный расход приёмки 600 л/мин. Вязкость A 100 сСт, B 40 сСт. Партия 6 000 л, доля B 30%, A 70%; смешивание 15 мин, проверка 10 мин, фасовка 200 л/мин.

В «Ускоренной фасовке» изменена только производительность фасовки: 400 л/мин. Результаты за одинаковые 480 мин и одинаковые поставки вычисляются моделью:

| Показатель | Базовый режим | Ускоренная фасовка |
| --- | ---: | ---: |
| Обслужено автоцистерн | 10 | 10 |
| Среднее ожидание обслуженных, мин | 0 | 0 |
| Оставшиеся в очереди | 0 | 0 |
| Готовый объём, л | 90 000 | 108 000 |
| Завершено партий | 15 | 18 |
| Незавершённых партий | 2 | 2 |
| Средняя обработка завершённой партии, мин | 59,67 | 40,00 |
| Загрузка приёма, % | 69,79 | 69,79 |
| Загрузка ёмкости смешивания, % | 100,00 | 100,00 |
| Загрузка лаборатории, % | 33,33 | 39,58 |
| Загрузка фасовки, % | 94,79 | 57,29 |
| Условная стоимость готового литра, ₽/л | 92,086 | 92,062 |

Выпуск растёт на 18 000 л, или 20%, при удвоении скорости фасовки: ограничение переходит на смешивание и контроль. Машина, уже находящаяся на посту в конце смены, не включается в очередь. На HTML-странице `/model/` таблица рассчитывается из функции симуляции во время сборки, а в интерактивном сравнении — из параметров сохранённых сценариев.

## Модель и расчётные допущения

- Единицы: минуты, литры и объёмные доли. Температура фиксирована, объёмы аддитивны, потерь нет. Килограммы, нагрев, давление, турбулентность и вязкость готовой смеси не рассчитываются.
- Симулятор — чистая функция `simulate(parameters, untilMinutes)`. Он пересчитывает начальное состояние до абсолютного модельного времени, продвигаясь по событиям. Частота кадров и скорость воспроизведения не входят в расчёт.
- Один пост приёма удерживает машину на подготовке, перекачке, ожидании свободной вместимости и завершении. Частичная разгрузка возможна; заполненный резервуар блокирует дальнейший приём, а не переполняется.
- Вязкость доставляемого компонента меняет расход по синтетической монотонной таблице: 40, 100, 200, 300 сСт → 1,00; 0,80; 0,60; 0,45 с линейной интерполяцией. Диапазон ввода ограничен 40–300 сСт. Это не паспортная характеристика насоса.
- Перекачка: `t = объём / (номинальный расход × коэффициент вязкости)`. При коэффициенте 1: `12 000 / 600 = 20 мин`, без подготовки, завершения и очереди.
- Компоненты партии: `A = объём × (1 − доля B)`, `B = объём × доля B`. Оба компонента списываются единожды при запуске партии, только при достаточных запасах.
- Один смеситель удерживает партию во время смешивания, проверки и ожидания свободной фасовки; освобождается при фактической передаче партии. Фасовка и лаборатория — ограниченные ресурсы. Заполнение ёмкости включено в время смешивания.
- Приёмный насос и условные линии подачи в цех считаются разными ресурсами. В лабораторию передаётся проба без отдельного материального расхода; все корректные партии успешно проходят проверку.
- Готовая продукция учитывается только после завершения фасовки целой партии. Незавершённый материал остаётся в партии смесителя или фасовки. Вывоз, возврат тары и вместимость склада не моделируются.
- Загрузка ресурса — занятое время / время наблюдения. Загрузка смесителя включает проверку и ожидание передачи. Среднее ожидание считается по обслуженным машинам; среднее время партии — только по завершённым партиям.
- Демонстрационные цены: A 80 ₽/л, B 120 ₽/л; удержание смесителя 6 ₽/мин, проверка 10 ₽/мин, фасовка 8 ₽/мин. Стоимость завершённой партии — её компоненты плюс фактическое время этих ресурсов. Приём и прочие затраты не тарифицируются. Стоимость литра — сумма стоимости завершённых партий / готовый объём; это не финансовая оценка объекта.

Ввод проверяется и в интерфейсе, и в вычислительной модели. Невозможная рецептура или нехватка компонента показывается причиной ожидания. Диапазон смены 30–1440 мин и ограниченные диапазоны параметров удерживают расчёт небольшим; отдельный Web Worker для этого набора не требуется.

## Изображения

Все одиннадцать активных видов (семь общих и четыре фронтальных) сгенерированы встроенным `image_gen.imagegen` с общими стилевыми референсами. Это обычные статичные иллюстрации, не 360°-панорамы и не настоящая 3D-сцена. Изображения не изменяются вместе с симуляцией; текущие числа выводятся интерфейсом отдельно.

Активный набор находится в `public/views/v2/`: общие виды P01–P07 и `detail-pump.webp`, `detail-valve.webp`, `detail-mixer-control.webp`, `detail-filling-control.webp`. Все имеют размер 1672 × 941, общий объём около 3,3 МБ. Виды загружаются по необходимости, исходные PNG сохранены отдельно. Метки накладываются на полный кадр без обрезания. Предыдущий набор остаётся в `public/views/` как версия 1.

## Границы и развитие

Авторизация пока отсутствует: это известное ограничение, а не выполненное требование полного хакатона. Нет серверного хранения, ERP/MES/1С, реальной промышленной телеметрии или утверждений о высокой нагрузке. Макет ограничен небольшим участком, без расширения до целого завода.

Чтобы добавить настоящую панораму или WebGL-тур, сохраните `TourPoint` как описание камеры/процесса и замените компонент просмотра изображения на панорамный проигрыватель или Three.js/React Three Fiber. Направление взгляда и связанные метрики уже отделены от визуального носителя.

Чтобы перенести вычисления на сервер, замените вызовы `simulate` адаптером API с контрактами `Parameters`, `SimulationSnapshot` и `SimulationResults`. Возможный серверный стек — Rust + Axum + Tokio, хранение сценариев в PostgreSQL + SQLx. Web Worker может быть промежуточным шагом при росте клиентских расчётов. VPS, Docker Compose и Caddy нужны только при соответствующем способе размещения. Заявления о масштабировании требуют измерений, например k6 и Grafana.

## Версия 2: промышленное окружение и осмотр оборудования

Карта и интерфейс используют сине-белую палитру с акцентами `#0079c2` и `#005b9a`, вдохновлённую цветами Газпрома. Логотип и принадлежность реальному предприятию не заявляются. Янтарные потоки масла и жёлтые проходы сохраняют своё назначение. Соседние корпуса и трубопроводная эстакада продолжаются за край карты: учебный блок показан как небольшой фрагмент большого завода. Приглушённый контекст помечен «Вне модели» и не добавляет расчётных ресурсов.

Новые изображения показывают эксплуатируемую территорию: потёртые окрашенные поверхности, неоднородный бетон, коммуникации, крепления и окружающие производственные корпуса. В каталоге `public/views/v2/` находятся семь обновлённых общих видов P01–P07 и четыре отдельных фронтальных ракурса: насос, запорная арматура, пульт смесителя и фасовочная станция. В крупных планах камера направлена перпендикулярно основной плоскости объекта, чтобы детали управления было удобно осматривать.

Маршрут взаимодействия: **точка на карте → общий вид → отмеченный узел → фронтальный крупный план → состояние или настройки → явный перезапуск модели**. Кликабельные маркеры продублированы списком под изображением. На вкладке «Настройки» изменяется общий черновик следующего прогона; текущая симуляция продолжает использовать уже применённые параметры. Кнопка «Применить и перезапустить» сбрасывает время и запускает расчёт с новыми значениями. Расход, рецептура, объём партии, длительности стадий и производительность фасовки действительно влияют на независимую модель. Давление, угол открытия арматуры и механические неисправности не имитируются неподтверждёнными числами.

Данные узлов и их координаты отделены от интерфейса в `src/lib/inspection.ts`; просмотр реализован в `src/components/IndustrialViewer.tsx` и `IndustrialViewer.css`. Это сгенерированные статичные изображения с интерактивным HTML-слоем и текущими показателями симуляции, а не панорамы или видео.

Первая версия сохранена: `public/views/` содержит исходные семь WebP, `assets/source-views/` — их PNG, `assets/VIEW_PROMPTS.md` — прежние промпты. Новые исходники размещены в `assets/source-views-v2/`; промпты общих видов — в `assets/VIEW_PROMPTS_V2.md`, крупных планов — в `assets/DETAIL_PROMPTS_V2.md`. Координаты деталей дополнительно записаны в `assets/DETAIL_HOTSPOTS_V2.json`.
