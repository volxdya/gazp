# Цифровой двойник участка технических масел

Прототип для хакатона «Цифровой двойник предприятия и 3D-туры по производству».
Модель повторяет путь масла по ТЗ: **автоцистерна → приём → резервуары → подача в цех → смешивание → контроль качества → фасовка → склад**.

- **Внешний процесс — приём автоцистерн:** КПП → весы (брутто) → входной контроль сырья → слив в резервуар A или B → весы (тара) → документы → выезд.
- **Внутренний процесс — производство:** подача компонентов A и B в цех (60/40) → смешивание → контроль качества партии → фасовка в бочки 216 л → склад.

Процессы связаны через **уровни в резервуарах**: если резервуар полон, цистерна ждёт; если пуст, цех простаивает. Кроме того, у них **общие ресурсы** — лаборатория (проба каждой цистерны и контроль каждой партии) и насосная.

## Проблема → решение

| Сценарий | Оборот цистерны | План выпуска | Маржа смены |
|---|---|---|---|
| Как есть | ~100 мин | 75% | ~565 тыс ₽ |
| +1 пост слива | ~99 мин | 75% | ниже — стройка не помогает |
| Второй смеситель | ~99 мин | 88–100% | +~100–200 тыс ₽, узким местом становится лаборатория |
| **Цифровой приём + 2-й смеситель** | **~52 мин** | **100%** | **~761 тыс ₽** |

«Цифровой приём» — это предзапись поставок, поточный анализатор на посту слива (освобождает лабораторию) и электронные документы.
Числа считает дискретно-событийная модель `src/lib/twin/sim.ts` на одинаковом потоке цистерн (seed 42).

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # модель, связь процессов, токены и пароли
npm run build && npm start
```

Демо-доступы (кнопки на странице входа):

| Роль | E-mail | Пароль | Права |
|---|---|---|---|
| Руководитель | admin@neftebaza.demo | Admin#2026 | всё, включая пользователей и журнал безопасности |
| Диспетчер | operator@neftebaza.demo | Oper#2026 | моделирование, сценарии, журнал, API |
| Экскурсант | guest@neftebaza.demo | Guest#2026 | схема, 3D-тур, процесс, сравнение готовых сценариев |

В продакшене обязательно задайте `SESSION_SECRET` и `NEXT_PUBLIC_SITE_URL`.

### Деплой на Vercel (бесплатно)

1. Импортируйте репозиторий в Vercel. Для монорепы укажите Root Directory — папку этого проекта.
2. Задайте Environment Variables: `SESSION_SECRET` и `NEXT_PUBLIC_SITE_URL`.
3. Нажмите Deploy.

На Vercel состояние (зарегистрированные пользователи, журнал, сохранённые сценарии) пишется во временный каталог и периодически сбрасывается. Демо-аккаунты создаются заново при каждом старте. Для постоянного хранения подключите Upstash Redis или Neon Postgres и замените файл в `src/lib/server/store.ts`.

## Разделы

- **Схема участка** — мнемосхема сверху в реальном времени модели: цистерны, уровни A/B, потоки в трубах, смесители, линия, склад.
- **3D-тур** — изометрическая сцена на Three.js: 12 точек по пути масла с живыми статусами, анимация цистерн, цех без крыши со смесителями и фасовкой, переход «тур → этап процесса».
- **Процесс** — мнемосхема двух процессов с полосой резервуаров, узкое место, загрузка ресурсов, график и диаграмма Ганта по цистернам.
- **Сравнение** — 4 сценария + свой, рекомендация, сохранение сценариев на сервере.
- **Журнал** — системный аудит (входы, расчёты, ошибки), события процесса, пользователи и согласия; выгрузка в CSV.
- **API** — REST v1 с примерами и кнопкой «Выполнить».

## Соответствие требованиям

| № | Требование | Реализация |
|---|---|---|
| 1 | HTTPS | `src/proxy.ts`: HTTP → 308 на HTTPS в продакшене; HSTS и защитные заголовки в `next.config.ts`; cookie `Secure` + `HttpOnly` |
| 2 | Большие нагрузки | лимит 240 запросов/мин на IP в proxy; публичные пресеты с `s-maxage` для CDN; расчёт смены — единицы миллисекунд; локальный расчёт в браузере |
| 3 | HTML-данные сайта | семантика, `metadata`, Open Graph, JSON-LD, `robots.txt`, `sitemap.xml`, `manifest` |
| 4 | Актуальность | электронные документы, слоты поставок, поточные анализаторы — текущая повестка производств |
| 5 | API продукта | `/api/v1/*` (simulate, scenarios, journal, users), `/api/health`, Bearer или cookie |
| 6 | Вход и разделение прав | 3 роли, проверка на сервере в каждом методе и в proxy для `/app`; блокировка после 5 неудачных входов |
| 7 | Восстановление при сбоях | атомарный снапшот состояния `.data/state.json`, автосохранение сессии в браузере с баннером восстановления, `error.tsx` с кнопкой «Восстановить», fallback расчёта при недоступности сервера |
| 8 | Журнал событий | `src/lib/server/store.ts` → `audit()`; клиентские ошибки пишутся автоматически |
| 9 | 152-ФЗ при регистрации | отдельный неотмеченный чекбокс согласия, версия политики + время + IP, `/privacy`, пароли — PBKDF2 с солью |
| 10 | Тест на других устройствах | адаптив 375 px → 1920 px, облегчённый рендер 3D на сенсорных устройствах, fallback без WebGL |

## План проверки на устройствах

1. Телефон 375×812 (iOS Safari, Android Chrome): вход, 3D-тур, переключение точек, таймлайн, вкладки.
2. Планшет 768×1024 в обеих ориентациях: панель сценария под сценой.
3. Ноутбук 1366×768 и монитор 1920×1080: сцена и панель рядом.
4. Без WebGL: сообщение вместо сцены, остальные разделы работают.
5. Офлайн/сбой сервера во время расчёта: расчёт выполняется в браузере, показывается уведомление.

## Архитектура

```
src/
  proxy.ts                 HTTPS, лимит запросов, защита /app
  app/                     лендинг, вход, политика ПДн, /app, API route handlers
  components/scene/        Three.js-сцена (TerminalScene) и React-обёртка с метками
  components/app/          рабочее место: схема, тур, процесс, сравнение, журнал, API
  lib/twin/                модель (sim), сценарии, точки интереса, производные метрики
  lib/server/              криптография сессий и паролей, хранилище, HTTP-утилиты
```

Данные синтетические, интеграций с ERP/MES/1С нет. Участок вымышленный, планировка условная.
